## 你现在能验收什么

打开项目 → **实时 OBD → 开发与验证 → 离线演练 → 开始模拟采集**。以下步骤都在「开发与验证」内部；主故障码页用于真实诊断流程。

1. 先选「正常连接 · 有故障码」和「15 秒 · 快速演练」。软件会模拟一次读取并自动保存，也可以点「停止并保存」。
2. 到「实时数据」查看转速、水温、车速、负荷、进气温度和空气流量；同一指标收到两次采样后显示趋势。
3. 到「采集结果」看模拟码，以及故障发生时保存的转速和水温。它们与当前采样分开展示。
4. 回到「离线演练」，在历史中点「打开回放」。拖动时间条或播放，即使退出并重新打开程序也能查看记录。
5. 「导出记录」把本次原始响应和结果保存成一个 JSON 文件，方便后续分析。
6. 分别选择「无码」「车辆没有响应」「中途掉线」「不完整数据」演练，确认系统能区分这些情况，并保留已收到的证据。

所有数值、故障和车辆识别号都是演示数据。界面持续显示模拟来源，记录不会自动写入实车故障台账。

## 对短时接车有什么帮助

软件已具备「按顺序读取 → 边读边保存 → 到时间结束 → 离线回看」的基础流程。故障信息优先，随后采实时值；提供 15 秒、30 秒和 3 分钟演练预算。实际通信、保存会消耗时间，预算会提前留出收尾空间。

没有响应时会保存失败结果；掉线后保留此前数据；保存无法确认时停止新请求并显示异常。后续可依据缺项决定还需要采什么，减少现场反复试错。

**离线演练通过不等于实车验证通过。** vLinker FS BT 的固件输出和真实车辆通信仍需要单独验证。MX+ 继续保留给 RaceChrono。X431、PIWIS 和 Panda 采集，以及独立特殊功能/设码属于后续工作。主故障码页的清码为用户明确授权的独立操作；模拟/回放不能触发实车清码或设码。

## 接下来交付顺序（历史；部分已在生产页落地）

1. vLinker 连接层及录制样本测试，形成现场只读采集检查项。
2. 设备可用时先确认 Windows 连接与固件信息，再安排限时实车采集；不需要现在接车。
3. 离线分析实车数据，补充 981 对应的故障说明、参数定义和最小补采任务。
4. 特殊功能按明确功能逐项研究 X431/PIWIS 对照资料和访问条件，验证后才设计独立执行。

生产读码/清码/数据分析软件已另有入口，见 live guide；上表第 1–2 项的**实车**步骤仍未做。
