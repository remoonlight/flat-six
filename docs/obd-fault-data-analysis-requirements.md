## 1. 要完成的操作流程

读取车辆故障 → 勾选需要检查的故障 → 点击“实时数据分析” → 自动汇总所需数据 → 按单元查看实际反馈值。

用户也可以直接打开数据分析页，从左侧全部数据项目中自行选择。

## 2. 已确认的要求

### 统一收进 981 故障库

- 981、982 手册中的故障码都纳入本项目的统一 981 故障库，不另外建立一个供用户切换的 982 故障库。
- 面向的车辆仍为 2014 Boxster S（981）PDK。
- 合并的是故障知识。每条仍保留原始手册、页码和适用条件，便于核查同一故障在不同单元中的含义。
- 不删除现有原始资料。后续整理结果统一入库，原资料作为依据保留。
- 产品 UI 隐藏手册出处；适用性与未核实提示仍显示。

### 故障码页面

- 每条故障前加勾选框。
- 收起时只显示“诊断代码 + 问题”，默认收起其他内容。
- 点击标题展开详情；勾选只决定是否加入数据分析，不同时触发展开。
- 同一个代码如果来自不同控制单元，分别列在对应单元下，可分别勾选。
- 列表下方增加“实时数据分析”按钮，与现有清码按钮分开。
- 选择的故障决定跳转后默认勾选的数据；多个故障需要同一个单元的同一数据时，只读一份，并显示它关联哪些故障。

### 数据分析页面

- 新增“实时 OBD → 数据分析”入口。
- 左侧展示全部已整理的数据项目，结构为“控制单元 → 数据明细”，可以展开、搜索、勾选。
- 从故障码页面进入时，自动勾选相关数据；用户可以继续增减。
- 右侧展示选中项目及对应反馈值。
- 每批暂限 **8** 项，这是软件预算，不是适配器实测上限；超限由用户选一批，不丢项。硬件同时可采上限仍待实车测量。
- 保留设备状态栏、车辆最新信息记录、981 设码参考和 X431 资料。
- VIN 隔离、单批串行、过期/晚到结果不得冒充当前值。

## 3. “分栏”究竟长什么样

按本轮执行指令采用以下交互，并隐藏手册出处。

收起时，故障列表只占一行，例如：

> □ **P0571 — 制动灯开关 A 电路问题**　▸

点这行标题后，下方展开一个详情区域，顶部有三个小标签：

> **检查办法**　｜　**需要读取的数据**　｜　**问题说明**

点击哪个标签，就显示哪一类内容；默认显示“检查办法”。再次点击故障标题，整个详情区域收起。

来源文件名、页码及核查证据保留在内部，不在故障详情中提供入口；正文内嵌的来源说明也应隐藏。适用条件和未核实提示仍保留，避免误用。

## 4. 手册核查应交付什么

### 已有资料清点

本次只读核对 `data/seed/dtc/manuals/by-code/codes.json`：

- 含 981 来源：504 个代码。
- 含 982 来源：813 个代码。
- 两者共同包含：211 个代码。
- 仅含 982、可新增到统一库：602 个代码。
- 合并去重：**1,106** 个代码。

这 1,106 个是现有**索引**覆盖量，不是手册完整覆盖，也不是 OBD 已支持数量，更不是「仅 981 的 504 库」作为产品 CURRENT。原索引已经按代码合并过资料，后续需复核同码在不同控制单元、软件版本或手册条件下是否存在不同含义。

原件：`Z:\porsche\981\981_Boxster BoxsterS BoxsterGTS.pdf`（4,455 页）及 `982_Boxster BoxsterS BoxsterGTS.pdf`（8,160 页）。另有 Cayman 维修手册及 PDK 故障排查资料。部分字体的文字映射损坏，页面视觉内容仍可读；需要恢复文字并核对页面，不能把自动抽取或已有标题索引算作完整诊断核查。

正文证据：**1,081** 有诊断正文，**25** 仍仅索引。规范化候选：**939** 有参数对应，**167** 无，**50** 类候选。**完整诊断步骤核查 = 0**。索引外 **21** 个标题候选待核对，未入库。

### 每个故障需要整理的内容

- 诊断代码、中文问题名称、对应控制单元及适用条件。
- 手册要求的检查步骤，以及步骤的原始出处。
- 每一步需要观察的数据名称、单位、读取条件、需要持续观察还是只读一次。
- 手册明确给出的判断条件：例如必须在什么状态下观察，满足什么条件才算异常；没有依据就不填阈值。
- 所需数据当前能否读取：已支持、需要厂商诊断方法、无法通过 OBD 直接获取，或资料尚未核实。
- 对应读取方法与验证证据。面向用户显示数据名称，协议命令留在工程资料中。

### 检查项目分四类整理

1. **连续数据**：需要反复观察变化，进入实时采集列表。
2. **一次性信息**：例如软件标识、配置或故障发生时保存的信息，按需读取，不挤占连续采集额度。
3. **人工检查**：手册要求观察、测量或拆检的项目，显示为检查清单。
4. **待核实项目**：手册原文、读取方法或本车适用性不足，明确列出缺口。

上述分类为建议的数据整理规则。只有原文确实要求的项目才能标为“手册要求”；为了排查方便而补充的观察项需要单独标注。

## 5. 数据分析页的建议细节

### 左侧：选择项目

- 控制单元可以展开/收起，下面显示具体数据。
- 所有已整理项目都能查找；是否可采集单独显示。
- 已支持项目可以勾选采集；未支持项目保留可见，显示原因，不显示伪造的反馈值。
- 同名数据来自不同单元时分别保留，不跨单元合并。
- 显示“已选项目数 / 当前上限”；一次性读取项目单独列出。

### 右侧：查看反馈

- 数据名称、所属单元、当前值、单位、最近更新时间。
- 读取中、有效、过期、未支持、读取失败等状态。
- 本项目关联的故障代码。
- 有可靠依据时显示手册的观察条件和判断范围；没有依据时保留待判断状态。
- 开始/暂停采集。跳转时保留选择，是否立即开始采集见下方收敛建议。

### 超过上限

保留完整的“需要检查什么”清单，并提示总数与可同时采集数；让用户选择本批项目，剩余项目保持待采集状态。不能静默丢弃超出的项目。

当前软件上限 8；同时要看刷新周期。先核对 vLinker FS BT 资料和调度，再用离线测试，最后记录实车表现。演示上限 ≠ 硬件能力。

## 6. 收敛质疑与建议

### 质疑一：把 982 收进 981，是否就能照着 982 的方法读本车？

不能仅凭收录关系作此判断。同一个代码可能有不同单元解释、检查条件或读取方法。若只按代码覆盖旧条目，可能把有用的 981 依据替换掉。

**执行：一个统一故障库，同码保留条件分支；来源保留内部，适用性放在详情中。** 982 新条目全部收录，本车适用性尚未核实的条目也收录，但不直接沿用其读取命令或判断阈值。

这不会增加第二个车型库或要求用户切换车型；需要收敛的是“统一收录”与“已确认本车可用”的标记。

### 质疑二：“所有故障码总结要读的数据”是否等于每个故障都必须有实时数据？

有的检查需要人工操作，有的只需要一次性信息。强行为每个故障填实时参数，会增加无效采集，还可能遗漏真正的检查步骤。

**建议：全量交付按“每个故障都有明确的检查需求或资料缺口”验收。** 实时数据、一次性读取、人工检查、待核实都算有明确去向；不能把“待核实”计入已完成的手册核查数。

### 质疑三：是先交付 1,106 个代码的完整研究，还是先交付可使用的页面？

如果要求所有代码的原始步骤、读取方法和本车适用性全部核实后才能上线，新页面会被资料缺口长期拖住。

**建议：同一需求分两条验收线。** 页面先完成选择、跳转、采集与状态显示；资料逐条核查并显示覆盖进度。全量手册核查仍是必须完成的目标，不用“已收录数量”替代“已核实数量”。

### 质疑四：数据越多，是不是越方便判断？

需要核查“更多项目”对刷新速度的影响。项目数上限本身不足以说明体验，还要看到实际更新周期。

**建议优先保证选中关键项目的及时更新。** 超限时先由用户选择一批，不自动轮换隐藏项目；这样用户能知道当前究竟在观察什么。后续确有需要再增加分批自动采集。

### 质疑五：“实时数据分析”是否要自动给出坏了哪个零件的结论？

目前用户明确要求的是关联数据选择和实际值反馈。自动诊断还需要完整判断条件、观察时长和证据规则，不能只凭一个瞬时值作结论。

**建议本轮收敛为：实时值 + 故障关联 + 手册有依据的判断提示。** 自动维修结论、泛化 AI 分析和推荐更换零件另立需求。

### 质疑六：点击按钮后要不要立即读取？

为了减少短时接车时的操作，建议：设备和车辆状态有效、全部所选项目可读取且未超限时，点击“实时数据分析”后直接跳转并开始采集。存在未支持项目或超限时，先展示待选清单，明确处理后开始；不丢项，也不悄悄替换项目。

独立从菜单打开分析页时先选项目，再点开始。按执行指令采用此规则；有资料缺口时不自动开始，完整需求仍展示，用户可手动选择已支持部分采集。

## 7. 本轮执行决定

1. 三个分类标签；隐藏手册出处，保留内部追溯。
2. 实时值、故障关联与有依据的观察条件，不增加自动维修结论。
3. 每批暂限 8 项，明确是软件预算；超限手动选择，符合条件时由故障页跳转并开始。

统一收录 982 故障、左侧展示全部数据并可手选，均已确认，不再重复征求确认。

## 8. 功能验收清单

- 统一库可检索 982 新增条目，同码的条件分支、来源证据不被覆盖。
- 故障行默认收起，标题含代码和问题；勾选与展开独立。
- 按当前读取到的单元/故障勾选后，跳转的数据来源正确；同单元同参数去重，不合并不同单元的同名参数。
- 左侧全部项目可浏览；自动选择结果可手动修改，未支持项目明确说明。
- 超限有提示，完整需求清单仍在；采集结果显示时间和有效性。
- 掉线或过期不继续显示为有效实时值；模拟数据不混入真实诊断。
- 车辆信息按原规则补全当前涉及单元的最新有效信息，不因失败覆盖旧值。
- 全量资料核查有逐条进度及缺口清单，不能用数量充当原文或本车验证证据。
- 现有清码、设码参考和 X431 入口保持可用，本轮数据采集不增加编码或执行器动作。
