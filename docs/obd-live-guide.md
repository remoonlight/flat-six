# 实时 OBD：设备匹配、故障读取与数据分析

2026-09-13。权威需求：[requirements.md](requirements.md) §R5.1 / §R6、[ADR 001](adr/001-no-ecu-write.md)。交互规则：[故障与数据分析需求](obd-fault-data-analysis-requirements.md)。模拟演练：[离线演练说明](obd-offline-guide.md)。设计稿：[架构](obd-architecture.md)。资料：[data/seed/obd/README.md](../data/seed/obd/README.md)。

设备连接、读码、清码、保存、复读和故障关联数据分析**已实现并通过离线测试**。本次没有连接真实设备或车辆，没有执行实车清码。

## 页面与使用方法

主菜单顺序：OBD设备匹配设置 / 故障码 / 数据分析 / 车辆信息 / 设码 / 开发与验证。

1. 打开「实时 OBD → OBD设备匹配设置」，刷新端口，明确选择已配对的 vLinker FS BT，再点连接。端口号不能沿用以前的 COM9 猜测；系统列表取当前设备身份。MX+ 继续用于 RaceChrono。
2. 标题右侧分别显示适配器连接、车辆通信、点火与实际电压。适配器上电不等于车辆已经连接。无法确定点火时显示未知；转速为零不会自动显示关闭点火。旧数据过期后不能作为当前值使用。
3. 有近期控制单元应答后，在故障码页点击「读取当前故障码」。每个标准诊断响应单元分别列出已存储、待定、永久故障；某项没读到时显示读取不完整，已读到的故障仍保留。
4. 故障行显示「代码 + 问题」，默认收起。点标题查看「检查办法 / 需要读取的数据 / 问题说明」；手册出处在界面隐藏，适用性与未核实提示仍保留。前面的勾选框只用于选择故障，不会展开详情。
5. 勾选故障，点击下方「实时数据分析」。页面汇总全部相关需求，同一单元的同一数据只读一次；无法读取的项目也保留。资料存在缺口时，先看清提示，再手动开始已支持部分。
6. 数据分析左侧按单元列明细，可搜索、勾选，点名称查看说明；右侧反馈值、单位、时间、关联故障和有效性。每批暂限 8 项，超出时手动选择一批，不自动丢项；显示实际批次耗时。暂停或离开页面会停止后续采集，旧值标为历史值，晚到结果丢弃。独立从菜单进入时，先选数据再开始。
7. 列表下方「一键清除故障码」面向当时在线、支持标准排放诊断清除的单元。软件先确认当前连接及车辆身份、保存清前故障，再发送一次清除并复读。永久码由车辆自行验证消除；收到应答、复读没有故障、仍有故障、结果未知分别显示。超时后停止该连接，不自动重发清码。
8. 「车辆信息」自动保存本次有有效回应的单元信息。已确认车架号的车辆，每个单元只有一条最新有效记录；重复读取更新这条记录。缺失字段不覆盖旧值，变化与观察日期另行显示。没有车架号的采集单独标为未识别记录，不与已有车辆合并。VIN 变化隔离旧结果，不把上一辆车的采样接到下一辆。
9. 读码、清码与数据分析使用同一独占队列，不并发争用同一连接。
10. 原实时数据、就绪监控、模拟采集、回放、手工查码和台账集中在「开发与验证」。「设码」保留 981 社区功能库和 X431 参考，不执行编码写入。

## 当前准确范围

- 首批协议是 11 位 CAN、500 kbit/s 的标准排放 OBD：Mode 03/07/0A 故障、Mode 04 清除，以及 Mode 09 VIN、标定号、标定校验值。数据分析已实现 16 个 Mode 01 基础参数（转速、负荷、水温、燃油修正、进气压力/温度/流量、节气门、点火提前角、车速、催化器传感器温度、控制单元电压等），每个单元先查支持列表，不能借用别的单元的数据。实际适配器输出与本车应答仍待接车验证。
- 不能把标准响应地址直接称为 DME、PDK 等保时捷模块。厂商地址与扩展诊断尚未核实；未支持单元单独列出，不冒充全车无码。**完整厂商诊断未实现。**
- 软件支持保存硬件号、序列号、软件号、标定号、校验值和编码指纹及其变化，但当前标准协议只能取得车辆实际提供的 VIN/标定信息。硬件、软件版本和编码尚无经过验证的专用读取方法，因此通常显示未知。标定校验值不能当作软件版本或编码指纹。
- 统一 981 库含 982，共 **1,106** 个索引代码；**1,081** 个有诊断正文证据，**25** 个仍仅索引。**939** 个有规范化候选数据需求，**167** 个尚无参数对应，共 **50** 类候选。**完整诊断步骤核查 = 0**。另有 **21** 个索引外标题候选待核对，未合并入正式库。候选 ≠ 本车可读。P0571 / PSM 4340 / P0420 有部分人工核对检查要点。逐码清单：[数据需求核查](research/obd-manual-data-needs.md)。原件 `Z:\porsche\981`。
- 每批 8 项是临时软件限制，不是 vLinker 硬件最大值。官方公布的链路速率不能换算成固定项目数；还需测量车辆应答和实际刷新耗时。[vLinker FS BT 官方规格](https://vgatemall.com/products-detail/i-52/)
- X431 默认列表仅首屏 7 项有原始证据，剩余顺序及标准响应地址对应关系待补充。因此排序机制已就位，但完整 X431 顺序尚未达到实车验收标准。
- 设码/刷写/执行器未开放。Mode 04 清码是 ADR 001 唯一写例外。

## 工程验收

`npm test` **131** 项通过（domain 94、数据库 17、OBD 20）；生产构建通过。Windows PowerShell 通信进程用替代串口的虚拟流验证了实际进程的异步收发，无硬件访问。

四组相关 Electron 界面验收通过（临时 SQLite + 隔离测试传输）：

- `npm run accept:obd-analysis-ui`（折叠、勾选、三标签、隐藏出处、跳转、超限、模拟反馈、暂停/离页、晚到结果）
- `npm run accept:obd-production-ui`（读码/清码、未支持单元、清后仍有码、VIN/单元档案）
- `npm run accept:coding-guide-ui`（981 设码库 + X431）
- `npm run accept:obd-ui`（开发与验证：模拟/回放）

隔离测试模式要求显式测试开关和临时目录数据库，不能写日常车库库。

全量桌面 TypeScript 检查仍有既存 `LocatorGlbViewer.tsx` 的 three 类型/空值问题；本次 OBD 文件没有新增错误。不把完整 desktop `tsc` 计为通过。离线通过不能代替实车验收。
