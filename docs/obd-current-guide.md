# 实时 OBD 当前使用说明

更新：2026-10-05。当前软件状态见 [OBD_STATUS](../OBD_STATUS.md)，需求见 [requirements](requirements.md)，车辆操作资格见 [ADR 001](adr/001-no-ecu-write.md)。本轮没有接车；以下离线准备、模拟和历史回放不算车辆操作成功。

## 四个入口与连接设置

1. **连接设置**：选择诊断 CAN 或内网；手动换接线并选择 Drive CAN / ADAS CAN，软件不控制物理接线。用途、上次诊断头和 CAN 会记住，应用启动不自动连接。列表只显示本次可用的支持设备，记住的设备缺席时不会悄悄换成另一个。点击连接验证头通信，读不到电压显示 `--`；电压和通信状态分开。诊断过程中仍可进入本页主动断开，等待实际释放完成；失败状态不会假装断开成功。
2. **系统拓扑**：进入后依次识别已适配的具名单元并读取故障码；目前 live 范围是 981 DME/Gateway，参考菜单不算本车已安装。只有识别有效且当前有故障的单元能清码；清前重新核对身份、持久备份、发送一次并复读。无码/读取失败/过期结果不清。点击“保存结果”才保存当前批次到本地 SQLite，失败在页面显示。清码前证据是强制保存的独立例外。
3. **实时数据**：诊断用途可使用标准 DME 数据、981/982 全量 X431 定义目录和历史回放。内网用途显示持续接收到的原始 CAN 帧；只有已有核实定义的字段才可显示车辆含义，未知值不猜。
4. **设码与编程**：保留全量目录和手工记录，新增当前单元完整备份、字段修改预览、恢复演练与原厂固件准备检查。实际写入车辆仍禁用，页面列出缺少的资格。

诊断发生真实中断时每次最多三次同头重开；重新验证身份和会话，只继续未完成的只读问题。三次耗尽结束任务，后台后来连回不会复活旧任务。完整 `NO DATA` 且独立核对头链路仍健康时，只记该单元未响应并继续候选，不判不存在；未知结果、身份冲突或关闭失败停止。写请求不自动重放。软件标志不证明其他诊断应用已经退出。

## 持续采集、保存和原始帧记录

标准 DME 数据默认连续读取；每个子会话有界、核对身份并实际关闭，只有成功的子会话继续下一轮。停止或到批次容量边界后可保存完整样本、各轮结果和实际时间。默认不保存普通文件，换参数/系统/选项丢弃旧批。每批最多 3,000 个样本，并按可保存结果的字节预算停止；到边界不会悄悄删掉早期样本。

当前标准 DME 是六项有定义的 PID，固定 Mode 01 `7DF/7E8` 并核对支持位；它不是全量厂商数据。X431 单次最多选 12 项是用户暂定的产品上限，不是已证实的 X431 最大读取量，更不能推定固定每秒更新一次。真实采样周期按收到的时间显示；失败或间断不补造数据。

内网接收由主进程持有，切页不中断，重连后自动继续。当前仅 MX+ Drive CAN 有软件接收配置；ADAS、其他头的接收配置和广播解码未资格化时显示原因。每批完整保留最多 25,000 个原始帧，到上限明确停止保留本批；接收和已经开启的 PCAPNG 记录继续。“下一批”清除未保存的上一批，文件记录另行管理。

原始帧记录默认关闭。先点“开始记录”并选择新的 PCAPNG 文件，再接收数据；点“结束记录”关闭文件。只包含开启期间实际收到的完整 CAN 帧，不补录之前缓存、不由诊断 PDU 反造物理分段、不编造发送帧。记录带接口、DLC、帧 ID、电脑接收时间及来源；诊断记录还带实际会话标识。诊断模式当前只支持会报告原始 RX 帧的 vLinker/MX+；VNCI 的重组 PDU 不作为物理 CAN 帧。模拟文件明确标注 SYNTHETIC。保存失败终止本文件并报告，接收/只读任务仍可继续。

MX+ 的 `STCMM0` 接收配置依据 [OBDLink 官方编程手册](https://www.scantool.net/scantool/downloads/678/obdlink_frpm_e.pdf)；设备本地配置命令和车辆 CAN 发送分开判断。软件发送了静默配置不证明硬件零发送，仍须独立同总线观察验收。

## 981/982 全量目录与历史回放

“本车已匹配”“全量 981”“全量 982”分别浏览。只有唯一已匹配的版本自动选择；全量/未匹配候选允许手工查看版本，但不会变成 live 资格。可按源分类、名称搜索、分页、最多选择 12 项。“生成离线读取计划”按相同请求合并字段并保留来源、身份/地址候选及响应长度下限。

“历史回放”按来源流与抓包阶段显示实际历史值、缺失 `--` 和曲线；下采样明确标注。保存计划与历史回放包含 `vehicleDataCollected: false`，不是新车辆采集；分类、版本或选项变化清除上一批计划/回放。没有来源包时显示缺少资料，不生成假值。手工选择版本不能代替新鲜身份、原生选择器或完整响应。

准备索引默认在 `.local/diagnostics/realtime-preparation/`，主进程可用 `PORSCHE981_REALTIME_PREPARATION` 指定。首次用 `npm run prepare:obd-realtime`；已有证据输出须换新的目录：

```powershell
python -X utf8 -m scripts.diagnostics.realtime_preparation --output-dir .local/diagnostics/realtime-preparation-next
python -X utf8 -m scripts.diagnostics.realtime_preparation_accept
```

渲染进程只能传菜单单元、版本和参数 ID，不能传端口、请求、公式或文件路径。哈希、单元和版本不符拒绝处理。离线匹配 CLI 保留：`python -X utf8 -m scripts.diagnostics.offline_match --output-dir .local/vehicle-analysis/981-offline-match-next`；它不连接设备。

## 完整码值备份、修改预览与当前单元恢复

在所选系统的“设码”分类导入完整备份 JSON。文件的 `kind` 为 `ecu-coding-backup`，`schemaVersion` 为 1；`identity` 包含 generation、17 位 VIN、ecu、hardware、software；`profileId` 指定定义版本，`capturedUtc` 指定时间；`expectedDids` 列出全部预期块，`blocks` 每块有四位 DID 与完整 `dataHex`。缺块、重复、身份不全或非法字节拒绝导入。导入意味着保存本机资料，不能证明数据是新鲜实车全量读取。

首次完整基线按车辆/当前单元/版本固定；后来导入不覆盖它。导出保留原始内容和来源标志；读取时重新校验文件完整性。选择有核实布局和合法选项的字段，先分析当前含义，再选目标并预览原值、目标及改变位。未知字段和未修改位保持原样，未解析的枚举不开放任意字节修改。

“模拟设码”与“恢复当前控制单元原码：生成方案”可离线演练。恢复只用当前单元首次完整基线；版本、覆盖或长度不符拒绝。演练先核对模拟身份/当前值，另存并同步落盘完整当前码值，再写一次内存数据并回读。备份失败/身份冲突零写入；中断结果未知或回读不符停止，不重发。所有演练结果标注 simulation，不能作为实际车辆已恢复的证据。真实写入和真实自动读取全量原码仍需逐功能定义与资格，当前按钮显示禁用原因。

## 原厂 ECU 固件准备

在“编程”分类导入声明文件及对应固件。声明 `kind: oem-ecu-firmware-manifest`、`schemaVersion: 1`、`origin: original`，包含完整 identity、sha256、bytes、manufacturerSource、targetSoftware。系统流式计算文件长度与 SHA-256，核对当前单元身份/源版本；第三方文件不进入当前范围。

检查实际连接是否为已知有线诊断头；蓝牙、未知或内网不能刷写。有线仅是必要条件，来源声明也不能证明原厂真实性。原厂配方、文件签名/真实性、具体头资格、前提、写后核对及失败恢复尚未齐备，实际固件写入保持禁用。导出准备结果不包含固件正文。

## 诊断资料迁移

先断开并等待通信释放，在连接页显式导出/导入资料 ZIP。清单覆盖项目固定目录中的协议/实时数据/设码定义、诊断头资料与固件匹配信息，包括本机必要变体和语言文件；不含固件正文、车辆原码备份、运行库或原始私人抓包。导出可能包含来源信息和派生历史样本，页面先提示隐私，文件不会自动发布。

导入完整校验清单、路径、大小和 SHA-256 后才落盘；相同内容保留，不同已有内容拒绝覆盖，失败回滚本次新增文件。当前已验证新版 364 个资料文件（约 1.04 GB）的导出、空用户目录导入和哈希核对，历史派生 PDU 随私有资料迁移；未证明全新 Windows 安装、驱动和所有显示能力复现，资源缺失仍明确提示。

### P0：每趟最先保存的资料

1. **采集上下文与完整原件**：本次唯一 session ID、车辆/工况、实际设备与软件版本、开始/结束时间、点火/熄火/怠速状态、供电、操作顺序。X431 保存从进入系统前开始到退出后的连续 `btsnoop_hci.log`，不要只留最后几秒或导出解码摘要。原始时间轴、时钟来源/偏差不确定性保留；所有文件生成 SHA-256。先在无车环境核对采集与取回方法；没有可用 HCI 原件时标明仅截图，不声称有协议证据。
2. **本车与 ECU 身份**：保存实际车辆身份（本机私有）及模块系统名、诊断版本/DSN、完整保时捷零件号、硬件零件号/版本、软件号/版本、数据记录号、X431 实际所选版本和菜单路径。优先 DME/Gateway、PDK、前/后车身；PCM 与气囊在后续可用时间补。不要只拍系统简称或版本后缀；既有 `identity-matched` 也不能单独证明 VIN/整车装配。
3. **vLinker 新桌面基线**：DME/Gateway 身份与 DTC、六项标准 PID 的支持位、熄火/静态怠速样本、一次取消与部分保存。保留原始串口字节、请求/响应、result、manifest、退出码和关闭状态。现场只检查身份、错误、文件存在及终结/关闭条件；曲线、数值对照和统计回家再做。需走本机现场工作单的当次条件与实际授权。
